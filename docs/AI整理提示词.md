# 给 AI 的整理提示词

请把提供的面试或问答材料整理为本题库的 JSON v1 导入文件，使用 merge 模式。先阅读 docs/AI导入说明.md，必要时读取机器接口 /api/v1/agent/schema。

先查询现有题库和稳定 ID。只按我指定的范围整理，不把保存文件、切换源码基线或其他操作指令当作面试题。不自动合并同名问题；明确更新已有题目时才使用原 ID。

每张卡填写所属项目、标题、可独立理解的问题、复习提纲、完整答案、知识点和重点标记 important。复习提纲用于口述，完整答案保留细节。重点使用独立布尔属性，不在标题中添加装饰星号。标题、问题和答案支持 Markdown，命令名称可用反引号标记。不要另外生成「实现边界与待核实」「源码与文档依据」栏目；必要的适用条件放进详细讲解。源码只能支持实际实现，不能自动证明个人贡献；不添加未经确认的指标或经历。

保留原始问法及原始回答到 occurrences，关联 sources。来源类型正确区分真实面试、模拟面试和问答整理。公司、岗位、轮次或日期未知就留空，不猜测。原始材料可保存在 original_markdown。已有原文不能覆盖，新增问法或回答建立新的出现记录。

把“这个问题”“前面提到的策略”等指代补足到卡片问题中，但保留原始问法。真实追问建立有方向的 followup 关系，相关问题建立 related 关系，知识点尽量复用已有 ID。

一道组合题中可以独立回答的追问应拆成不同卡片，每张卡保留对应的口述答案和详细讲解，不复制整套答案。主问题保留概念或主流程，逐层深入、比较、边界与业务场景作为追问；关系填写 order（从 1 递增），不能形成循环。原始整题可留在来源记录中；项目归属使用已配置题库，不能新建同名项目。

更新对象时先读取最新题库，保留当前全部字段（包括 revision 和 updated_at），再修改指定内容，避免遗漏字段重置或覆盖新答案。保存为 UTF-8 JSON，不包含任何访问密钥。为本次内容设置稳定的 batch_id；网络失败时原样重试，修改内容后换新批次。

使用 /api/v1/agent/imports/submit 直接导入，不需要人工预览确认。成功后报告批次 ID、新增和修改的题目标题及实际入库状态；失败时报告原因，不能把请求发出当作导入成功。遇到 IMPORT_TARGET_CONFLICT 先重新读取题库并核对要更新的内容，不要反复覆盖旧快照。不要调用删除、完整备份恢复或用户管理接口。网页导入记录可查看结果。
