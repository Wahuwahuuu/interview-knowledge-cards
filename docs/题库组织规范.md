# 主问题与追问的组织规范

每张在用卡片都应该是一道可以直接用于面试的问题。主问题与追问表达面试中的承接关系；项目和知识点标签负责分类。不能为了收拢题目，另造一个宽泛的总括入口。

## 主问题必须有明确的提问对象

- 能说清在问哪个机制、哪两个方案、哪种异常或哪个完整任务，回答有明确边界。
- 基础概念可以成为主问题，例如“什么是联合索引”“什么是 KV Cache”。概念必须有实际考点，不能只是栏目名称。
- 比较题可以独立，例如“RabbitMQ 和 Redis Stream 如何选型”。不能再人为增加“消息中间件如何选型”统领所有产品比较。
- 完整算法或系统设计任务可以独立，例如链表反转、短链服务设计；不用为它们补“算法如何选择”“系统如何设计”等目录题。
- 不以主问题数量少、分组数量少为目标，也不把原文的第一句自动当作主问题。

“分布式系统需要解决哪些问题”“项目如何选择数据库”“如何从零设计某个平台”这类问法，需要检查是否只是分组用的总论。没有明确对象、条件和任务边界时，不作为入口；有实际内容时从已有材料中恢复具体问法。

## 追问必须接得上前一道题

判断关系时，想象面试官刚听完上一题的答案，接下来为什么问这一题。追问可以要求解释刚提到的机制、比较同一问题的另一种方案、改变条件或处理失败，但不能只因为共享关键词就挂在一起。

例如以下是三条独立问答线：

- RabbitMQ 和 Redis Stream 如何选型？
  - 两者的消费确认与失败恢复有何差异？
  - 什么业务依据会支持从 Redis Stream 切换到 RabbitMQ？
- RocketMQ 和 Kafka 的底层机制有什么区别？
  - 这些机制如何影响顺序、可靠性与吞吐？
  - 定时消息与普通记录时间戳的能力有何不同？
- Celery 是什么，与 Kafka 有什么区别？
  - 任务执行框架与消息中间件能否配合？
  - 直接接 Kafka Broker 时需要核对哪些适配限制？

具体案例可以作为追问，但不是所有具体题都必须依附于更抽象的题。例如“联合索引”到“最左前缀”再到给定范围 SQL 是自然深入；“Docker 与 Kubernetes 的区别”并不要求把 Kubernetes 的 CPU 配额整组藏在它下面。

## 问法与答案必须一起对齐

- 口述版以简洁、易记为目标，用尽可能少的字直接回答本题。通常用 1–3 个短句、约 40–100 字，保留必要条件和比较对象；不重复题目、不堆开场白，不把详细原理和案例塞进提纲。按结论、比较对象或步骤分行，优先使用少量短要点，并适度加粗关键词；不能为追求简洁而把全部内容挤在一段，也不要每个词都加粗。较复杂题可适当增加，不能为压字数丢掉关键结论。
- 详细讲解承接原理、推导、示例、失败路径与版本条件。口述版可以提示记忆顺序，完整答案负责说明为什么及何时成立，两者都要独立对应当前问题。
- 每张追问离开分组后也要能读懂。把“如何验证”“有哪些取舍”“失败怎么办”中的对象补全。
- 优先沿用已有问题与答案中的明确场景，不编造个人项目、组件版本、数据规模或实测结果。已有答案只是方案示例时，题目也不能改成声称实际做过的经历。
- 主问题变具体后，口述答案必须直接回应它；不要只改题名，还保留一整套无关总论。拆分答案时保留对应细节和来源。
- 拆题时由整理者逐题核对口述版和详细讲解的含义。关键词重合、段落序号、答案非空都不能证明配对正确；不得按相似度直接截取段落后自动入库，也不得在匹配不足时拿第 N 段填第 N 条追问。
- 比较题的答案必须覆盖题目列出的全部对象和比较维度。例如询问 B+ 树、Hash、二叉搜索树的范围查询与磁盘访问，不能只写 B+ 树和 B 树的结构差异。原文没有足够答案时，应查证后补齐，不能借用同组另一题的回答。
- 不同追问复用整篇讲解，或一个口述答案完全包含于另一题时，列为复核线索。重复本身不等于错误，也不应触发自动删除或强制改写；应判断每题的独立回答是否完整、贴题。
- 不为分组自动补概念卡。确实存在独立学习需求、且用户要求补充时，再新增有答案的具体题。

## 关系与展示

- 每个在用追问只保留一个直接父问题，填写明确的 `order`。
- 同主题但不能自然追问的题，独立展示，使用 `related` 关联。
- 追问通常控制在三层以内；不要为了层级完整添加没有独立价值的问题。
- 展示范围按实际提问组织，不改变用户配置的项目顺序。

## 原始资料与检查

普通导入不得擅自语义合并。用户明确要求全库整理或去重时，才判断同主体、同前提、同答案范围的重复问法。撤出的总括题与重复原卡归档留存，保留原问法、答案、掌握状态和来源；永久删除仍遵循二次确认。

整理前保存最新题库快照，逐题记录保留、改写、改关系或归档的去向。整理后检查在用题目完整覆盖、无环、无多父问题，以及原始卡片、来源和复习状态未丢失。保存前重读最新记录，发生内容冲突时重新核对；仅复习状态变化时保留用户最新状态。

真实题库、映射、快照和逐题清单保存在被忽略的私人目录，不提交到公共仓库。
